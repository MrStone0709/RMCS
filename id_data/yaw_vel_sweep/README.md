# 云台 yaw 速度环「参考注入」扫频测试 —— 闭环频响辨识

## 实验意义

在**保持 gimbal_controller 在线**的前提下，通过新增的 `VelocityReferenceInjector`
组件直接给速度环一个可编程参考，从而激励**真正的生产速度环**并获得其**闭环频响**。

这是判断"环路是否健康、带宽多少、能否提增益"的直接依据，比阶跃测试信息量更大。

## 配置

```yaml
gimbal_controller:
  yaw_control_enabled: true           # 保持在线
  yaw_velocity_command_input: true    # 打开速度参考注入

yaw_vel_injector:
  step_enabled: false
  sweep_enabled: true
  sweep_start_freq: 0.5
  sweep_end_freq: 30.0
  sweep_duration_s: 30.0
  sweep_amplitude: 1.5                # rad/s
  sweep_logarithmic: true
  csv_path: "/tmp/vel_sweep.csv"
```

电机仍在**力矩模式**（`control_angle` 恒为 nan），因此测到的是 gimbal_controller
的软件串级（角度环 → 速度环），不是电机内置环。

## 数据

`vel_sweep.csv`：31000 行 @ 1 kHz，31 s（含 1 s 前后保护段）

列：`update_count, elapsed_s, velocity_reference, /gimbal/yaw/velocity_imu,`
`/gimbal/yaw/velocity, /gimbal/yaw/torque, /gimbal/yaw/angle,`
`/gimbal/yaw/temperature, /gimbal/yaw/max_torque`

阶跃版本的实验见 `../yaw_vel_step/`。

### 指标

| 指标 | 值 |
|---|---|
| **直流增益** | **0.978**（−0.19 dB）|
| **−3 dB 带宽** | **18.1 Hz** |
| **开环穿越频率** | **≈ 12.26 Hz**（由闭环反推）|
| **相位裕度** | **≈ 67.8°** |
| 相干 >0.5 有效频段 | 0.49 ~ 21 Hz |

**相位裕度的求法（精确，无近似）**：由实测闭环频响反推开环频响

```
L(jw) = T(jw) / (1 - T(jw))
```

再找 |L| = 1 的穿越频率与对应相位：

| 7.08 | 2.23 | 6.96 | −100.0 |
| 9.03 | 1.73 | 4.77 | −104.8 |
| 10.99 | 1.27 | 2.08 | −108.6 |
| **12.26** | **1.00** | **0.00** | **−112.2** |
| 12.94 | 0.89 | −1.02 | −113.9 |
| 18.07 | 0.51 | −5.92 | −127.0 |
| 21.00 | 0.41 | −7.78 | −132.9 |

→ 穿越 12.26 Hz，相位 −112.2° → **PM ≈ 67.8°**

（此前用二阶近似估得 47.9°，该近似有误差，以本精确法为准。）

**与模型预测对比**：用辨识出的 `G(s)=1/(0.1155·s+0.932)` 和 `kp=13`
预测穿越频率 **17.9 Hz**、相位裕度 **55°**（按 6 ms 延迟假设）。

实测穿越 **12.26 Hz**、裕度 **67.8°** —— 同一量级且都很健康；
差异来自模型未计入的高频动态与延迟项。
**结论：环路是健康的，与辨识模型的判断一致。**

## 关键结论：上一轮"增益差 8 倍"是误判

连续阶跃测试（见 `../yaw_vel_step/staircase.csv`）曾观察到参考 1.0 rad/s 时
实测只有 0.44 rad/s，据此推断"有效增益 ≈1.6，比配置的 kp=13 小 8 倍"。

**本次闭环频响证明这个推断是错的**：

| | 之前推断 | 本次实测 |
|---|---|---|
| 闭环低频增益 | ≈ 0.12（疑似 8 倍折损）| **0.978（≈1，正常）** |

**真实的闭环增益接近 1，没有折损。**

### 那 0.556 rad/s 的稳态误差是什么？

是**库仑摩擦造成的死区（stick）**：

- 参考**恒定不变**时，轴会停在摩擦死区里；要产生约 0.9 N·m 的摩擦力矩，
  必须有速度误差让比例项输出对应力矩
- 扫频时轴**始终在运动**，摩擦表现为阻尼而非死区，所以增益正常

由此得出对调优有决定性意义的判断：

- ✅ **环路增益是好的 → 不要改 `yaw_velocity_kp`**
- ❌ **`yaw_velocity_ki = 0.02`（时间常数 50 s）太慢 → 消不掉摩擦死区误差**

## 安全观察（重要）

| 项 | 值 |
|---|---|
| 温度 | **33 → 50 °C**（30 秒内上升 17 °C）|
| 力矩 rms | **5.46 N·m**（电机额定 4.5 N·m）|
| 力矩峰值 | **11.23 N·m**（**正好撞上观测到的 11.29 N·m 电流上限**）|

温度曲线：

```
t:   0s   5s   10s  15s  20s  25s  30s
T:   33   33   33   34   35   40   49  °C
```

前 15 秒平稳，20 秒后急升 —— 对应扫频进入高频段，力矩随频率增大。

**两条警告：**
1. 宽频扫频（0.5→30 Hz）让电机**持续过载**，温度快速上升。
   **不建议长时间连续跑这种宽频扫频**；建议缩短到 15 s 或降低幅值。
2. 峰值力矩 11.23 顶到电流上限，说明高频段**控制器在饱和**，
   该部分数据的幅值被压缩。**>20 Hz 的数据分析时应排除**。

## 代码依赖

本实验依赖两处对原始工程的**最小侵入**改动（详见对应源文件注释）：

1. `gimbal_controller`：新增 `yaw_velocity_command_input` 开关（默认 false），
   为 true 且 `/gimbal/yaw/velocity_command` 有有限值时，直接以它作速度参考；
   角度环退出并 reset。三重回退保证不注入时行为逐字不变。
2. 新增 `VelocityReferenceInjector` 组件：产生阶跃/扫频参考并落盘 CSV。

### 踩过的两个执行器坑（重要）

**坑 1：输出/输入必须在构造函数体注册，不能在 `before_pairing`**

`executor.hpp` 的 `init()` 顺序：

```
① 444–521 行  遍历所有 output_list_/input_list_ → 建立 output_map
② 523–525 行  before_pairing()
③ 527–580 行  绑定（output_map.find）
```

`output_map` 在 `before_pairing` **之前**定型。若在 `before_pairing` 里
`register_output`，该输出不会进 map，消费方 `find` 失败；若消费方是
`required=false` 的输入，会**被静默跳过**（`ready()` 永远 false，无任何日志）。

**坑 2：注入器不能读它所注入对象的输出**

执行器把**所有输入（含 required=false）都算作依赖边**。
本组件给 `gimbal_controller` 提供速度参考，若再读它的 `control_torque`，
就构成循环依赖 → `Circular dependency found` FATAL。
需要对照记录时，用独立的 `ValueCollector`（只读不写，不参与依赖环）。

## 复现方式

```bash
cd id_data/yaw_vel_sweep
python3 compute_closed_loop_frf.py vel_sweep.csv
```

脚本为纯 Python 实现（迭代 radix-2 FFT），不依赖 numpy/scipy。
输出闭环幅频/相频/相干、−3 dB 带宽；开环反推 `L=T/(1-T)` 的手算过程见上文表格。
